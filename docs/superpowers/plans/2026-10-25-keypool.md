# KeyPool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship the approved private API-pool dashboard and gateway at https://api.praritsidana.com.
**Architecture:** React dashboard and one Node service, SQLite persistence, encrypted upstream secrets, model aliases and shared quota groups. A dedicated Docker Compose project under /opt/apikeywebapp sits behind the existing Nginx.
**Tech Stack:** TypeScript, React, Vite, Express, Node 24, SQLite, Undici, Docker, Nginx.
**Spec:** docs/superpowers/specs/2026-10-25-keypool-design.md (approved by user).

## Global Constraints

- Production domain api.praritsidana.com; repository prarit0097/apikeywebapp.
- Everything belonging to the application on VPS lives under /opt/apikeywebapp except its dedicated Nginx and certificate configuration.
- Never modify unrelated apps, databases, containers or ports; never stop shared services.
- No secrets in Git, logs, public endpoints, or localStorage.
- Unknown capacity is Unknown; shared quota groups never count twice; paid credentials default disabled for routing until opted in.
- No live-provider success claims without real owner credentials and an actual installed-client test.

## Review Focus

- Private-network upstream URLs, IPv6 and rebinding: block before connecting and reject redirects.
- Partial stream and client cancellation: no fallback or duplicate generation once dispatch is ambiguous or output starts.
- Parallel allowance spending and restart: reservations and quotas persist atomically.
- First-owner setup races and cookie mutations: single setup and exact-origin CSRF protection.
- Secret disclosure: management responses, repository contents and errors must remain sanitized.
