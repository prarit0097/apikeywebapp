# Super key pooling and live quota plan

User requested automatic multi-platform pooling, quota-exhaustion failover and always-visible total/used/balance. This refines the already-authorized app; user requested continuous implementation without further check-ins.

## Design

- A built-in `super` alias automatically targets the first configured model on every enabled, policy-eligible provider. Provider priority determines initial selection. Explicit existing aliases retain their configured targets. Super pooling allows cross-provider/model fallback as directly requested; responses/capabilities may differ.
- Add unique account/project group allowances once, never once per key. Sum comparable fixed allowances, or same-period allowances with the same reset schedule. Mixed periods/schedules and unknown pools are explicitly incomplete; no invented universal balance. Example: 10M + 3M + 3B = 3,013,000,000.
- Dashboard shows total allowance, gateway-recorded used tokens, conservative reservations, estimated remaining, individual super-key usage and freshness. Per-key usage and shared-pool usage are distinguished. Gateway usage across all client apps is recorded centrally. Usage made directly against providers remains unknown.
- Authenticated GET /v1/quota exposes the same current summary to any client holding a gateway key. Dashboard refreshes every five seconds while visible, without overlapping polls. Secrets remain excluded.
- Exhausted local allowance skips to the next candidate. Explicit upstream rate/quota/credit rejection also fails over; shared groups cool down together. Try candidates once within the existing overall deadline rather than stop after three exhausted keys. Never retry ambiguous dispatch or a partial stream.
- Preserve production data with additive SQLite migration and an online backup before deployment. Use only /opt/apikeywebapp and its existing dedicated app resources.

## Acceptance limits

No provider key was supplied for live model tests. No claim that arbitrary protocols work or that provider quotas can literally transfer. A successful controlled failover proves gateway behavior, not free model entitlement. The display is manual/estimated unless provider-reported balance is actually available. Daily/monthly reset scopes must not be added to lifetime balances as one exact budget.
